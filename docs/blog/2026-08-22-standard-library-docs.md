# The Standard Library, Documented

*August 22, 2026 · The Jo Team*

Until now, the honest answer to "what is in Jo's standard library?" was: read the
source code inside [`lib/`](https://github.com/typescope/jo/tree/main/lib). That
works — the sources are short and the doc comments are good — but it asks a lot
of someone who just wants to know what integer division does on divide-by-zero,
or whether the operation they call `filter` is spelled `select` here.

Starting with 0.12.5, the standard library API documentation is published at
[jo-lang.org/stdlib](https://jo-lang.org/stdlib/), and every release ships its
own copy.

[![The Jo standard library documentation, showing the jo.Int class](/img/stdlib-doc.png)](https://jo-lang.org/stdlib/0.12.5/)

## What is in it

Everything the compiler knows about a namespace, organized the way the language
organizes it. Sections, classes, interfaces, abstract types, objects, type
aliases, patterns, functions and context parameters each get their own group.

Signatures are shown as the type checker sees them, which means effects are
visible:

```jo
def println(s: StringLike): Unit receives stdout
```

That trailing `receives` clause is the part you cannot get from a signature in
most languages. `println` writes to standard output, so it says so — and a
function that does not declare it cannot reach standard output at all. That is
checked by the compiler, not left to convention. Browsing the standard library
is one of the better ways to build an intuition for how Jo's
[capabilities](../overview/capabilities.md) read in practice.

## The same tool you already have

None of this is bespoke. The documentation generator ships in the compiler, and
the standard library docs are built by running it over `lib/`. The same command
documents your project:

```sh
jo doc
```

It reads the selected module's `doc-options` from `jo.toml` and writes a self-contained directory to
`.build/<module>/doc/` — no web server, no build step, open `index.html` in a
browser:

```toml
[module.api]
doc-options = ["--title", "Agent API", "--readme", "README.md"]
```

The version shown beside the title in the header comes from your module's
package version, so documentation carries the version of the thing it documents
without you having to wire anything up:

```toml
[module.api.package]
name = "agent-api"
version = "1.4.0"
```

Modules that declare no package show `version unknown`. For the lower-level
interface, [`jo compile --doc`](../usage/commands/compile.md) takes source files
directly and accepts `--project-version` explicitly; it remains experimental.
See [`jo doc`](../usage/commands/doc.md) for the full set of options.

## Versioned, and staying that way

Each Jo release now attaches its standard library documentation as a release
asset, and the site publishes every version of the docs available in compiler
releases:

```
https://jo-lang.org/stdlib/0.12.5/
```

The site navigation links the newest version. Older versions stay exactly where
they were published, so a link you saved keeps working, and changing the version
in the URL takes you to the one you want.

## Feedback

Coverage is not complete. Some public APIs are not documented yet, and others
describe what an operation does without saying when you would reach for it. Both
are being filled in over coming releases.

Gaps are worth reporting in the meantime. If a doc comment is missing, wrong, or
unclear, open an issue on [GitHub](https://github.com/typescope/jo). The same
goes for the generator itself — if `jo doc` produces something confusing for
your own project's shape, we would like to see it.

To try any of this, start with the [install guide](../usage/install.md), then
run `jo doc` in a project of your own.
